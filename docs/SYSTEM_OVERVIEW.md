# System overview

The integration owns rooms, zone metadata, mappings, number/select entities, the native sidebar and persistent irrigation strategies. The controller app owns the decision loop and actuator calls. The pure crop-steering-engine package provides testable phase decisions.

The frontend reads HA state and Recorder history. Its setup and strategy actions use response-bearing services with explicit room IDs and revision checks. A saved draft does not change active irrigation. At a local lights-on boundary, an armed strategy supplies one versioned, expiring snapshot of effective per-zone parameters. The controller validates that snapshot and retains a durable required-strategy latch once a strategy takes control.

P0 waits for its additional morning dryback (3% below the highest reading since lights-on unless changed) or its latest first shot, P1 ramps toward the moisture target, P2 maintains moisture with EC-sensitive thresholds, and P3 ends scheduled irrigation: the zone dries to its dryback target and is held there by rescue-sized shots, with the emergency-floor rescue beneath. Controller dryback is a relative percentage of the detected peak; VWC itself is an absolute percentage and measured drying rate is percentage points/hour.

A room with a reservoir mapped also has nutrient batches: the integration keeps its batch settings, feed recipes and feed schedule (Reservoir page) and publishes the feed plan for the stage in use, the schedule's week or one picked by hand; the controller refills the reservoir (the pump and recirculation from half-way through the fill), doses each doser in the stage's recipe's order and recirculates, holding the room's shots meanwhile. With the reservoir's level set up, no shot takes it under its minimum: a refill comes first, planned from the room's next round of shots, or watering waits.

The live loop applies sensor, enable/interlock, volume and duration gates before hardware sequencing. Readback failures latch shared equipment out. Home Assistant going away leaves every relay as it was, so as it shuts down for a restart or an update the integration switches each room's mapped pumps, valves and dosers off while the devices are still connected: the one time the integration switches hardware, and only ever off. A power cut, a crash or a network drop gives it no such chance; only a device's own failsafe covers those. Local tests exercise these branches with fake HA; production hardware behavior still requires site verification.
