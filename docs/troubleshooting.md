# Troubleshooting

A notification or Repairs card that ends with a code such as **CS-101**: look the code up in
[Error codes](ERROR_CODES.md) (the same list is in the dashboard under **Help → Error codes**)
for what it means, what happens to watering meanwhile, the likely causes and what to do.

| Symptom                                            | Check and action                                                                                                                                                                                                                                                                                                                                                                        |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Workspace requests an integration update           | Update the integration including its bundled www/dashboard.html, restart HA and refresh the page.                                                                                                                                                                                                                                                                                       |
| Strategy cannot arm                                | Check controller capability/heartbeat, strategy validation, sensor freshness and explicit limits. Save the draft before arming.                                                                                                                                                                                                                                                             |
| Strategy is armed but not active                   | It becomes active at the next local lights-on after arming. Arming never enables the engine. If the controller's heartbeat or a probe was stale at lights-on, or Home Assistant was restarting, it activates at the first minute it can; Repairs shows *irrigation strategy has not moved on to today* with the reason until then. |
| Active strategy is held or in error                | Repairs shows *irrigation strategy is holding its zones* with the reason. While held, the controller still waters the P3 emergency and watchdog shots, and a dead probe's timed schedule; only the strategy's steering waits. Restore valid fresh data; use disarm for an explicit return to manual targets at the next lights-on. Do not bypass the required-strategy latch. |
| Setup refuses a zone change: *The irrigation strategy is armed…* | A strategy that is armed or running manages a fixed set of zones. Disarm it (Irrigation strategy → Schedule), wait for it to return to draft at the next lights-on, change the zones, then use **Update zones from setup** and arm it again. |
| Mapping save is rejected                           | The message names each entity and why: **it is ON** (turn it off and submit again), **it reads 'unavailable'** (the device must be reachable and OFF), or **entity not found** (check the id, or its device integration has not loaded). The wizard keeps everything you typed and shows the same step again. Also check entity domains/units, duplicate valves and revision conflicts. |
| Probe rejected for its unit                        | Pore EC is accepted in mS/cm, dS/m and µS/cm; moisture in % or m³/m³. Other units are converted exactly or refused. `ppm` is refused because the 500 or 700 scale is not something a sensor reports: expose the probe's EC reading instead.                                                                                                                                             |
| Room saved but never waters, and it has one switch | A zone needs only its valve; pump and main-line valve are optional. Under **Shared room hardware** choose *Zone valves only*, map the single switch as the zone's valve and leave pump and main-line empty. One switch cannot be used in two roles.                                                                                                                                             |
| Room has a pump, shots are counted, VWC never rises | The room has never said how it is plumbed, so the controller works it out from what is mapped: an empty pump field means it never runs a pump, opens the zone switch and counts the shot as delivered. Open **Settings → Rooms & hardware** (or *Configure*), choose the layout with a pump, choose the pump, save. From then on a missing pump holds the room instead of running it dry; see the [first-run review](audits/2026-09-21-first-run-review.md). |
| Setup stops with *Home Assistant is still running PHASE Control X, but Y is installed* | HACS replaces the files; Home Assistant goes on running the code it loaded when it started. Restart Home Assistant, then add PHASE Control again. The first setup screen, the add-a-room screen and the **Configure** menu all show the version that is actually running. A room set up on stale code keeps whatever that code created, entity ids included, and those are for life: the symptoms are a controller reporting *settings missing, running on built-in values* (CS-402), **Help** reading *Integration: not reported*, and entities called `number.<your device>_crop_steering_…`. The way out is to delete the integration, restart Home Assistant, and set it up again. |
| Repairs says *N setting(s) are not where the controller looks for them (CS-605)* | The controller and the dashboard find a setting by its exact entity id (`number.crop_steering_zone_1_plant_count`), and the listed ones are registered under another id, so the controller runs on its built-in defaults for them and reports *settings missing, running on built-in values* (CS-402). Keep the engine off. One or two listed: an entity id was edited; change it back under Settings → Devices & services → Entities → the entity → the cog. Nearly all listed: the room was created while Home Assistant was still running an older integration (see the row above); delete the entry, restart Home Assistant, add it again. The card clears by itself, and nothing is renamed for you. |
| Repairs: *kill switch helper missing (CS-601)*, asking for `input_boolean.f2_control_enabled` | Only a room that really is gated by that helper (an install from before the setup wizard) needs it: create it as a Toggle helper and leave it OFF until you are ready to water. **On a room made by the wizard, do not create it.** Such a room has its own kill switch, *Engine Enabled* (`switch.crop_steering_engine_enabled`); the helper would be a second one that does nothing. See [CS-601](ERROR_CODES.md#cs-601). |
| Alert: *moisture reading hasn't changed (CS-101)*, but the sensor shows a value | The controller treats a reading that has not **changed** for 20 minutes as a dead probe, and waters that zone on a timed safety schedule instead (a shot every 90 minutes by default, within the daily cap). This is deliberate: a probe pulled out of its cube keeps reporting a steady number, and the plant it left behind still needs water. It also happens to a probe sitting in a cube with **no plant in it**, or pegged at its maximum in a soaked one, because nothing is drinking and the number never moves. Expect it on a bench test; with a plant drawing water it clears by itself. A room with nothing growing can be switched off (**Switch room off…** on the Overview, *Room Active* in Home Assistant), which stops its notifications. See [CS-101](ERROR_CODES.md#cs-101). |
| **Help** shows *Controller: not reported* (or *Integration: not reported*) | *Controller: not reported*: the controller app is not running, or has not reported for this room yet. Start it and wait one loop (up to a minute). *Integration: not reported*: the room has not loaded; check it under Settings → Devices & services. The two parts carry one version number: if **Help** shows two different ones, update the older part. |
| Notification: *plumbing and switches disagree, not watering (CS-202)* | The room's declared plumbing and its mapped switches contradict each other (it says it has a pump and none is mapped, or the other way round), so the controller will not water it. Nothing is wrong with the hardware. Fix it in **Settings → Rooms & hardware**: map the missing switch, or change the plumbing to what the room really has. The hold clears by itself once the new setup is adopted (kill switch and hardware OFF, as for any setup change). |
| Setup refuses to save: *The plumbing for this room is set to […], but no pump switch is chosen* | You said the room has a pump (or a main-line valve) and did not choose one, or cleared one that the layout needs. Choose the switch, or change the plumbing if the room really has none. |
| Mapping saved but controller has old data          | Compare setup revision with controller acknowledgement. Wait for rediscovery and inspect app logs.                                                                                                                                                                                                                                                                                      |
| Room/zone disappeared                              | Check Settings → Rooms & hardware for archived entries. Restore the same ID; do not reuse IDs for different equipment.                                                                                                                                                                                                                                                                  |
| No recorded EC line                                | Confirm mapped EC entities are recorded in HA Recorder and have data in the selected time range. A target line is not a sensor history.                                                                                                                                                                                                                                                 |
| Shot volume disagrees with observation             | Verify litres per plant, plant count, drippers/plant and actual L/h; run a catch test. Inspect duration caps and physical pressure/flow.                                                                                                                                                                                                                                                |
| Source code change did not reach controller        | Use Update/Rebuild. Restarting an existing container keeps its old image.                                                                                                                                                                                                                                                                                                               |
| Hardware fault (CS-301) stays                      | Set every room that shares the pump or valves to **Watching only** (watering off), and check the switch the alert names, at the device and in Home Assistant. Once every pump and valve reads OFF, the hold clears within a minute; then switch watering back on. |
| Embedded theme does not match                      | Use the integration's same-origin sidebar and choose **Home Assistant** under Settings → General → Appearance. Cross-origin standalone pages cannot read parent theme variables.                                                                                                                                                                                                                                                  |
| Live connection failed                             | Reauthenticate HA or configure the explicit connection in Settings. The dashboard never shows sample data in place of your room.                                                                                                                                                                                                                                                                      |

Use [INSTALL.md](INSTALL.md) for repository links and commissioning steps. The public repository must contain the intended revision before guided installation can obtain it. Browser or unit-test success does not prove that an older deployed image has changed.
